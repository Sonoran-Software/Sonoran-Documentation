---
title: Send Files
description: Send image, video, audio, PDF, and external file links to a connected user in CAD.
---

`POST` `https://api.sonorancad.com/v2/general/photos`

> **Rate limit:** `10 requests per minute`\
> Authenticated v2 endpoints are rate limited per API key rather than per IP address.

Send files to a user in your CAD community. The existing `/v2/general/photos` route and SDK method names are unchanged.

## View and attach photos in CAD {#view-and-attach-photos}

Files sent through this endpoint appear in **Recent files**, where users can preview images, videos, audio clips, and PDFs, or open external links.

In the custom record builder, add an **Evidence** section. When filling out a record, click **Select evidence**, select the files to attach, and click **Attach selected**. You can also use **Add file URL** to attach a link directly. Click an attachment to preview it, then save the record to keep the attachments. Record PDF exports include clickable file links.

Existing **Image** fields continue to support photos: click the folder icon, choose a photo, and click **Use photo** or **Replace photo**.

<Note>Multiple files and Evidence sections are available on CAD staging. Existing single-photo requests remain compatible with production.</Note>

## Request Body {#request-body}

Authenticate with `Authorization: Bearer YOUR_API_KEY`.

- `communityUserId` (required): the recipient's community user ID in the authenticated community.
- Supply exactly one of `url` (one URL) or `urls` (an array of 1–30 URLs). Each must be an absolute HTTPS URL without embedded credentials. Duplicate URLs are delivered once. The entire batch is validated before delivery.
- `fileType` (optional): `image`, `video`, `audio`, `pdf`, or `link`. Applies to every URL in the request; use it for extensionless or signed file URLs. Without it, the type is inferred separately from each URL's path. Unrecognized paths in `urls` become external links; an unrecognized legacy `url` remains an image.

Supported type inference includes images (`jpg`, `jpeg`, `png`, `gif`, `webp`, `avif`, `bmp`, `svg`), video (`mp4`, `webm`, `mov`, `m4v`, `ogv`), audio (`mp3`, `wav`, `ogg`, `m4a`, `aac`, `flac`, `opus`), and `pdf`. Playback and embedded PDF viewing depend on the browser and file host; **Open file** is available when a preview is unavailable.

```json
{
  "communityUserId": "player-1234",
  "urls": [
    "https://cdn.example.com/evidence/scene.png",
    "https://cdn.example.com/evidence/bodycam.webm",
    "https://cdn.example.com/evidence/statement.pdf",
    "https://cdn.example.com/evidence/call.mp3"
  ]
}
```

To send an extensionless PDF, use `"urls": ["https://cdn.example.com/signed-file"], "fileType": "pdf"`.

<Tab title="SonoranCADFiveM">

Use this tab only when calling the v2 API from the server side of an in-game FiveM resource.

* **Sonoran.lua** and **Sonoran.js:** use the `sonorancad` export to get the ready CAD client.
* **Sonoran.Net:** FiveM exports do not return a .NET client. Read the Sonoran CAD convars and create a fresh client.

The API key is stored in `sonoran_apiKey` as a protected FiveM convar. FiveM restricts a convar after `add_convar_permission` is configured, so only explicitly permitted resources can read it. Grant another resource access with `add_convar_permission your-resource-name read sonoran_apiKey`. If you change the API key in `config.json`, fully restart the `sonorancad` resource before reading the updated convar value.

## Response {#response}

Successful requests return `application/json`. The `delivered` value counts recipient CAD connections, and `files` counts distinct file URLs. Delivery confirms routing to those connections, not that the browser loaded every file.

```json
{
  "communityUserId": "player-1234",
  "delivered": 1,
  "files": 2
}
```

The endpoint returns `400 Bad Request` for missing or invalid inputs and `404 Not Found` when the recipient has no eligible CAD connection in the authenticated community.
