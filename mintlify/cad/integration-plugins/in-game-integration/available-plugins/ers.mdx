## What is Emergency Response Simulator? {#what-is-emergency-response-simulator}

Emergency Response Simulator is a paid, third-party script for FiveM.

ERS adds cooperative emergency callouts for police, fire, EMS, and other services.

[ERS can be purchased from Nights Software.](https://store.nights-software.com/category/ersgamemode)

## Activation Guide {#activation-guide}

### Download and Install the Resource {#id-1.-download-and-install-the-resource}

<Info>

This submodule is included with the [Sonoran CAD FiveM resource](/cad/integration-plugins/in-game-integration/fivem-installation). Enable it using the configuration step below.
</Info>

Night ERS `1.8.16` or newer is required. Start `night_ers` before `sonorancad` where possible. If ERS starts later or is restarted, the integration reconnects automatically.

### Adjust the Configuration {#id-2.-adjust-the-configuration}

Open **Admin > Integrations > FiveM**, select the server, then open **Emergency Response Simulator (ERS)**. Enable the plugin with the header toggle and review the settings below. Changes save automatically. When saved, run `exec @sonorancad/sonorancad.cfg` in your server console to apply them.

See [Submodule Configuration](/cad/integration-plugins/in-game-integration/submodule-configuration) for requirements, reset, and migration details.

### Ensure Players are Linked {#id-3.-ensure-players-are-linked}

Players must [link their CAD account](/cad/integration-plugins/in-game-integration/link-user-in-game) and have an active CAD unit before accepting callouts. To receive ERS callouts assigned from CAD, they must also be on an ERS shift with a service selected.

### Update CAD Record Templates {#id-4.-update-cad-record-templates}

Review your templates in **Admin > Records and Codes > Custom Records**. The resource includes example character, license, and vehicle registration templates in `sonorancad/submodules/ersintegration/SonoranCAD Records`.

Use the plugin's record-field pickers to match your existing templates. If you choose to import the examples, review any replacement of your community's existing templates first.

### Check the Connection {#id-5.-check-the-connection}

Run `sonorancad ers` in the **server console**. It shows whether ERS is running, whether its callout list has reached CAD, and the reason for the most recent failure. Check that the integration is running and the callout catalog says `synced to CAD` before testing callouts from the live map.

If a check fails, use the [troubleshooting steps below](#troubleshooting). The integration retries loading and sending the callout list automatically.

## Configuration {#configuration}

### Record field mappings {#record-field-mappings}

Select a row in **Civilian field mappings**, **Vehicle registration field mappings**, **License field mappings**, or **BOLO field mappings**, then click the destination field on the record preview. Each row pairs an ERS value with one CAD field; these lists have fixed source values.

Use **License type field** to select the destination for the license type. **License type mappings** maps each ERS license category to its CAD label and validity. Use **Warrant description field** and **Warrant flags field** to pick their destinations as well. Stock record template IDs are managed automatically; a **Custom … template** selector only appears for an existing nonstandard template override.

In **Developer Mode**, **Return age from DOB string** and **Generate date** open the Lua callback editors for age and date calculations. These are separate from the record-field mappings.

## Features {#features}

### Live Map Callout Generation {#live-map-callout-generation}

Dispatchers can use the live map to create a new ERS callout at a specific location.

Drag-and-drop the `ERS` icon from the toolbar to a location on the map. Clicking the new ERS map icon will allow you customize the callout and settings.

### Record Lookups {#record-lookups}

Use ERS to request a person's information or a vehicle's information. When ERS returns that information, the integration creates the corresponding CAD records for lookups. Accepting a callout alone does not create every person and vehicle record for that call.

### Automatic Call Generation and Assignment {#automatic-call-generation-and-assignment}

#### ERS to CAD {#ers-to-cad}

1. With `create911Call` enabled, an ERS callout offer creates a mapped 911 call in CAD.
2. A linked player with an active CAD unit accepts the callout **inside ERS**.
3. With **Create dispatch call on acceptance** enabled, Sonoran CAD creates the dispatch call and attaches that player's unit. With **Attach accepting unit** enabled, additional players who accept the same callout are attached to that call too.

<Info>

Using `/dn respond` on a Sonoran dispatch notification does not accept the callout inside ERS. Use ERS's own callout controls to accept it.
</Info>

#### CAD to ERS {#cad-to-ers}

1. A dispatcher attaches another online unit to that ERS-generated dispatch call in Sonoran CAD.
2. The integration sends the matching callout to that player's ERS session.
3. The player can see and continue the callout in-game.

This only applies to dispatch calls generated by the ERS integration. The player must be online, linked to Sonoran CAD, and on an ERS shift with a service selected.

### Call Locations and Postals {#call-locations-and-postals}

ERS calls use your [Sonoran CAD postals](/cad/integration-plugins/in-game-integration/available-plugins/postals) when available, including custom postal files. If that lookup is unavailable, the integration tries your postal resource when using resource mode, then a postal supplied by ERS. A call can still be created with `Unknown postal` if none are available.

If postals differ between CAD and the game, check that the CAD postal settings use the map data your community expects.

## Troubleshooting {#troubleshooting}

Start with `sonorancad ers` in the **server console**. It shows enabled features, connection status, callout-list status, and the last failure so you can check the part that is failing.

| Problem | What to check |
| --- | --- |
| The integration is disabled or ERS is not started | Enable **Emergency Response Simulator (ERS)** for the selected server. When the automatic save finishes, run `exec @sonorancad/sonorancad.cfg` in your server console and confirm `night_ers` is started. |
| The ERS version is too old | Update Night ERS to `1.8.16` or newer and restart it. Older versions are blocked. An unverified version is a warning; confirm your installed ERS version before continuing. |
| Callouts are missing from the CAD live map | Confirm ERS has callouts enabled and loaded. If the callout list could not be sent to CAD, check the CAD connection and configured server ID. The integration retries automatically. |
| A 911 call appears, but no dispatch call appears | Enable **Create dispatch call on acceptance**, link the accepting player to CAD, and have them clock in with a CAD unit before accepting the callout inside ERS. |
| A unit assigned in CAD does not receive the ERS callout | Confirm the player is in game, linked to CAD, and on an ERS shift with a service selected. The CAD call must have been generated by this integration. |
| Calls work, but person or vehicle lookups do not | Request the information through ERS first. Check the imported CAD record templates and any record configuration issues reported by `sonorancad ers`. Database Sync communities also need the option below. |
| A record is rejected because a value already exists | Check the relevant CAD template's unique fields, such as a plate number. Correct the duplicate value or template setup; a failed record does not necessarily mean call creation is broken. |

If the issue continues, give [Sonoran support](https://support.sonoransoftware.com) the action that failed and the error code shown. When support supplies an ID, run `sonorancad support <id>` in the server console. The report includes ERS connection and failure details. Support may also request `sonorancad getclientlog <playerId>` for a player who did not receive a callout.

## Limitations {#limitations}

### Database Sync {#database-sync}

When a community uses database sync, all record lookups run against that community’s external database. The ERS integration automatically creates characters and vehicles in the CAD database through the API, so these records must be included alongside the external database results.

To enable this, turn on [**Include CAD API records in DB Sync lookups**](/cad/integration-plugins/database-sync-and-merge#2.-combine-api-and-db-sync-records).
