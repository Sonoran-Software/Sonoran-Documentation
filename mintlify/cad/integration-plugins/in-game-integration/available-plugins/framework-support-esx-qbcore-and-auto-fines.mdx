## Activation Guide {#activation-guide}

### Download and Install the Resource {#id-1.-download-and-install-the-resource}

<Info>

This submodule is included but must be enabled for the framework running on your server after installing the [Sonoran CAD FiveM resource](/cad/integration-plugins/in-game-integration/fivem-installation).
</Info>

### Adjust the Configuration {#id-2.-adjust-the-configuration}

Open **Admin > Integrations > FiveM**, select the server, then open **Framework Support (ESX/QBCore) and Auto Fines**. Enable the plugin with the header toggle and review the settings below. Changes save automatically. When saved, run `exec @sonorancad/sonorancad.cfg` in your server console to apply them.

See [Submodule Configuration](/cad/integration-plugins/in-game-integration/submodule-configuration) for requirements, reset, and migration details.

### Ensure Players are Linked {#id-3.-ensure-players-are-linked}

Ensure the players have already [linked their CAD](/cad/integration-plugins/in-game-integration/link-user-in-game) for this integration to work.

### Configuration {#configuration}

Use **Framework** to select QBCore, ESX, or Legacy ESX. Select the framework and inventory actually running on your server; the selector saves the required configuration switches together.

<Accordion title="Framework">

| Setting | What it does |
| --- | --- |
| **Notification override** | Use a different notification system for this plugin or inherit the resource default. Choices: Use server default, ox_lib, Lation UI, pNotify, Chat. |

</Accordion>

<Accordion title="Fines">

| Setting | What it does |
| --- | --- |
| **Issue fines** | Allow eligible CAD records to trigger an in-game fine. |
| **Show fine notifications** | Notify players when the framework issues a fine. |
| **Using QB management** | QBCore only. Use QB Management when routing fines to job accounts. |
| **QB notify fined player** | QBCore only. Send the player a QBCore notification after a fine is issued. |
| **Forms that can issue fines** | Enter the exact names of CAD forms that can trigger in-game fines. |

</Accordion>

<Accordion title="Language">

Expand **Language** at the bottom of the plugin to edit its in-game messages. Keep substitution tokens such as `%s` or `{0}` intact.

| Setting | What it does |
| --- | --- |
| **QB fine message** | Text shown to players for QB fine message. Keep any substitution tokens in the text. |

</Accordion>

With **Using QB management** enabled, set **QB management account names** to the job accounts that should receive fines.

### Auto-Fines {#auto-fines}

Civilians in-game can be automatically fined for the crimes they commit based on fineable forms submitted.

Enable **Issue fines** and add the exact record names to **Forms that can issue fines**, such as `Arrest Report` or `Speeding Citation`.

The fines are pulled from your custom records:

* `Charges` section -> `Fine` field
* `Speed` section -> `Fine` field

## Usage {#usage}

This submodule can be used to issue fines to players when reports/records are entered into the CAD that include fines. You can configure the reports/records that are finable in the configuration. This submodule also adds support for ESX that other submodules can take advantage of. Currently, the following submodules are supported:

* [dispatchnotify](/cad/integration-plugins/in-game-integration/available-plugins/dispatch-notify)
  * Adds the ability to show character names in dispatch responses (officer names)
  * Adds the ability to restrict functionality to certain jobs (like police). See the [dispatchnotify documentation](/cad/integration-plugins/in-game-integration/available-plugins/dispatch-notify) for how to do this.
* [callcommands](/cad/integration-plugins/in-game-integration/available-plugins/call-commands)
  * Adds the ability to show character names for the caller when they use /911. This is automatic when the submodule is installed.
* [livemap](/cad/integration-plugins/in-game-integration/available-plugins/live-map)
  * Adds the ability to show character names on the map.

### Legacy ESX Support {#legacy-esx-support}

<Warning>

Legacy ESX Support utilizes MySQL-Async in order to get character information from your database directly. ESX requires this in older versions so this shouldn't be an issue.
</Warning>

This is mainly for ESX v1 releases that were made before the character system implementation using only the `users` database table. These versions of ESX used the `users` table only for player information of active characters and a `characters` table that held all character information (active and secondary characters of your players).

Due to different handling of character information such as first name and last names, this option allows you to use esxsupport submodule with older "Legacy" ESX v1 releases.

Select **Legacy ESX** under **Framework**.
