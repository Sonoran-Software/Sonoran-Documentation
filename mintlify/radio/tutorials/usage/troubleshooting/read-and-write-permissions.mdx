## SonoranRadio – Fix “Config File Is Read-Only” Error {#sonoranradio-fix-config-file-is-read-only-error}

The FiveM server needs to read its connection credentials and write local backups. If Radio reports a write error, check the permissions on the resource folder and the file mentioned in the server console.

***

### Step 1: Open Your Game Panel {#step-1-open-your-game-panel}

Log into the game panel where your FiveM server is hosted\
(e.g. **ZAP-Hosting, txAdmin, Pterodactyl, Gamepanel, VPS**).

***

### Step 2: Locate the Config File {#step-2-locate-the-config-file}

Find your `sonoranradio` resource folder, usually under `resources/[sonoranradio]/sonoranradio/`. If the message mentions the server ID, check this file:

```
resources/[sonoranradio]/sonoranradio/config.lua
```

***

## 🪟 WINDOWS HOSTS {#windows-hosts}

#### Step 1: Locate the file {#step-1-locate-the-file}

```
resources\[sonoranradio]\sonoranradio\config.lua
```

***

#### Step 2: Open file properties {#step-2-open-file-properties}

1. Right-click `config.lua`
2. Click **Properties**

***

#### Step 3: Allow Read & Write access {#step-3-allow-read-and-write-access}

1. Under the **General** tab:
   * ❌ Uncheck **Read-only**
2. Click **Apply**
3. Click **OK**

In **Properties > Security**, verify that the account running FiveM can read and write the file. For backup errors, it also needs permission to create files in the `sonoranradio` folder.

***

#### If it keeps reverting to Read-Only {#if-it-keeps-reverting-to-read-only}

Apply the change to the entire folder:

1. Right-click the **`sonoranradio`** folder
2. Click **Properties**
3. Uncheck **Read-only**
4. Click **Apply**
5. Select **Apply changes to this folder, subfolders, and files**
6. Click **OK**

***

## 🐧 LINUX HOSTS {#linux-hosts}

(ZAP-Hosting, Gamepanel, Pterodactyl, VPS)

#### Step 1: Open your game panel or file manager {#step-1-open-your-game-panel-or-file-manager}

Log into the panel where your FiveM server is hosted.

***

#### Step 2: Locate the config file {#step-2-locate-the-config-file-1}

```
resources/[sonoranradio]/sonoranradio/config.lua
```

***

#### Step 3: Fix file permissions {#step-3-fix-file-permissions}

Grant read and write access to the account running FiveM. For backup errors, that account also needs permission to create and rename files in the resource folder. Keep `config.lua` private because it contains the API key.

If the game panel supports file permissions:

1. Right-click `config.lua`
2. Select **Permissions**
3. Apply the change

⚠️ If your panel does **not** allow permission changes, contact your hosting provider and ask them to make the file writable.

***

### Linux File Permissions – Quick Reference {#linux-file-permissions-quick-reference}

Each permission digit is the sum of:

* **4** = Read (r)
* **2** = Write (w)
* **1** = Execute (x)

#### Common Permission Values {#common-permission-values}

* `0` = --- (No access)
* `4` = r-- (Read only)
* `6` = rw- (Read + Write)
* `7` = rwx (Read + Write + Execute)

#### Permission Structure {#permission-structure}

```
OWNER | GROUP | OTHERS
  X   |   Y   |   Z
```

If the FiveM process owns the file, `600` gives it read and write access. The process also needs access to the parent directories.

***

### Final Step: Restart SonoranRadio {#final-step-restart-sonoranradio}

After correcting the permissions, run the restart command in the FiveM server console.

```
exec @sonoranradio/sonoranradio.cfg
```
