If you’re using a release that predates **FiveM Settings**, see the [previous guide](https://github.com/Sonoran-Software/Sonoran-Documentation/blob/8c017dc2fe962a3b750d4b34bb53aa0fb72bcb54/mintlify/radio/tutorials/usage/troubleshooting/error-codes.mdx).

This page documents the structured error and warning codes emitted by the Sonoran Radio FiveM resource.

Direct links can target any code on this page using fragments such as `#err-121`. Structured logs also include a short link such as `https://sonoranradio.com/error/ERR-121`.

## Current Resource Codes {#current-resource-codes}

### Errors {#errors}

#### ERR-101 {#err-101}

**Internal Key:** `ERR_OX_LIB_NOT_STARTED`

**Meaning:** ox\_lib must be started before Sonoran Radio when that dependency path is used.

**First Troubleshooting Step:** Start `ox_lib` before Sonoran Radio and restart the resource.

#### ERR-102 {#err-102}

**Internal Key:** `ERR_OX_LIB_INIT_LOAD_FAILED`

**Meaning:** Sonoran Radio could not load `@ox_lib/init.lua`.

**First Troubleshooting Step:** Verify that `ox_lib` is installed correctly and that `init.lua` exists.

#### ERR-103 {#err-103}

**Internal Key:** `ERR_OX_LIB_NOTIFY_UNAVAILABLE`

**Meaning:** `ox_lib` notifications were selected, but `lib.notify` was unavailable.

**First Troubleshooting Step:** Confirm `ox_lib` is running and initialized without errors.

#### ERR-104 {#err-104}

**Internal Key:** `ERR_RADIO_ITEM_INVENTORY_MISSING`

**Meaning:** **Require an inventory item** is enabled, but no supported inventory resource was detected.

**First Troubleshooting Step:** Start `qb-inventory` or `ox_inventory`, or set **Require an inventory item** to **Disabled** in **FiveM Settings > Inventory**. Restart the resource.

#### ERR-105 {#err-105}

**Internal Key:** `ERR_RADIO_ITEM_FRAMEWORK_MISSING`

**Meaning:** **Require an inventory item** is enabled, but no supported framework resource was detected.

**First Troubleshooting Step:** Start `qb-core` or `qbx_core`, or set **Require an inventory item** to **Disabled** in **FiveM Settings > Inventory**. Restart the resource.

#### ERR-106 {#err-106}

**Internal Key:** `ERR_API_CREDENTIALS_MISSING`

**Meaning:** The API key or community ID is missing from configuration.

**First Troubleshooting Step:** Download the resource for the intended community and server from **FiveM Installation**. For a manual installation, check the Community ID and API key in `config.lua`. Restart the resource.

#### ERR-107 {#err-107}

**Internal Key:** `ERR_API_FATAL_DISABLED`

**Meaning:** A fatal API error disabled radio API functionality until the issue is corrected.

**First Troubleshooting Step:** Fix the reported API or community configuration issue, then restart the resource.

#### ERR-108 {#err-108}

**Internal Key:** `ERR_API_CRITICAL_ABORTED`

**Meaning:** A request was aborted because the resource is already in a critical API error state.

**First Troubleshooting Step:** Resolve the earlier fatal API error before retrying requests.

#### ERR-109 {#err-109}

**Internal Key:** `ERR_FRAMES_DEPARTMENTS_MISSING`

**Meaning:** The resource could not load the rules for the selected **Frame permission mode**.

**First Troubleshooting Step:** Open **FiveM Settings > Permissions and frames > Frame access**. Check **ACE frame permissions** or **Frame department permissions** for the selected mode, then restart.

#### ERR-110 {#err-110}

**Internal Key:** `ERR_JAMMERS_PERMISSION_MODE_INVALID`

**Meaning:** The configured permission mode for radio jammers is invalid.

**First Troubleshooting Step:** Select a supported **Jammer permission mode** in **FiveM Settings > Jammers > Access**, then restart.

#### ERR-111 {#err-111}

**Internal Key:** `ERR_RADIO_ITEM_CONFIG_MISSING`

**Meaning:** **Require an inventory item** is enabled and the resource could not load the radio item settings.

**First Troubleshooting Step:** In **FiveM Settings > Inventory > Radio item**, verify **Radio item ID** matches the item in your inventory. You can also disable **Require an inventory item**. Restart the resource.

#### ERR-112 {#err-112}

**Internal Key:** `ERR_SCANNER_ITEM_CONFIG_MISSING`

**Meaning:** **Require an inventory item** is enabled and the resource could not load the scanner item settings.

**First Troubleshooting Step:** In **FiveM Settings > Inventory > Scanner item**, verify **Scanner item ID** matches the item in your inventory. You can also disable **Require an inventory item**. Restart the resource.

#### ERR-113 {#err-113}

**Internal Key:** `ERR_QBOX_OX_RADIO_ITEM_MISSING`

**Meaning:** The configured radio item does not exist in Ox Inventory on Qbox.

**First Troubleshooting Step:** Add the item to `ox_inventory/data/items.lua` and match its name in **FiveM Settings > Inventory > Radio item > Radio item ID**. Restart the server.

#### ERR-114 {#err-114}

**Internal Key:** `ERR_QBOX_OX_SCANNER_ITEM_MISSING`

**Meaning:** The configured scanner item does not exist in Ox Inventory on Qbox.

**First Troubleshooting Step:** Add the item to `ox_inventory/data/items.lua` and match its name in **FiveM Settings > Inventory > Scanner item > Scanner item ID**. Restart the server.

#### ERR-115 {#err-115}

**Internal Key:** `ERR_COMMUNITY_CHANNELS_FETCH_FAILED`

**Meaning:** Community channels could not be fetched from the radio service.

**First Troubleshooting Step:** Check the HTTP status in the server log and verify API connectivity.

#### ERR-116 {#err-116}

**Internal Key:** `ERR_SKIN_SAVE_FAILED`

**Meaning:** A radio skin configuration file could not be saved.

**First Troubleshooting Step:** Verify that the target file path is writable by the server process.

#### ERR-117 {#err-117}

**Internal Key:** `ERR_CONFIG_SAVE_FAILED`

**Meaning:** A JSON configuration file could not be saved.

**First Troubleshooting Step:** Check file permissions and confirm the resource directory is writable.

#### ERR-118 {#err-118}

**Internal Key:** `ERR_SERVER_IP_SET_FAILED`

**Meaning:** Sonoran Radio could not register or update the server IP with the radio service.

**First Troubleshooting Step:** Verify the Community ID, API key, and server ID from **FiveM Installation**. Check outbound HTTPS connectivity to the Radio API.

#### ERR-119 {#err-119}

**Internal Key:** `ERR_SERVER_IP_INVALID_ROOM`

**Meaning:** The radio service returned an invalid `roomId` while setting the server IP.

**First Troubleshooting Step:** Check the API response and confirm the configured community is valid for radio.

#### ERR-120 {#err-120}

**Internal Key:** `ERR_FRAMES_CONFIG_MISSING`

**Meaning:** The resource could not load the frame access settings.

**First Troubleshooting Step:** Check the selected server in **FiveM Settings** and restart the updated resource. If you're upgrading from local settings, [run the migration](/radio/game-integrations/fivem/installing-the-in-game-resource#migrate-existing-settings).

#### ERR-121 {#err-121}

**Internal Key:** `ERR_SERVER_SPEAKERS_SET_FAILED`

**Meaning:** Sonoran Radio could not synchronize in-game speaker locations with the radio service.

**First Troubleshooting Step:** Verify placements in **FiveM Placements > Tone speakers** and check the API response in the server console.

#### ERR-122 {#err-122}

**Internal Key:** `ERR_SERVER_NAME_SET_FAILED`

**Meaning:** Sonoran Radio could not update a user display name in the radio service.

**First Troubleshooting Step:** Verify API connectivity and confirm the target user exists in the linked community.

#### ERR-123 {#err-123}

**Internal Key:** `ERR_INVALID_COMMUNITY_ID`

**Meaning:** The configured community ID is invalid or not enabled for the API.

**First Troubleshooting Step:** Confirm the configured community ID belongs to a community with radio API access.

### Warnings {#warnings}

#### WRN-201 {#wrn-201}

**Internal Key:** `WRN_LB_PHONE_NOT_STARTED`

**Meaning:** lb-phone integration is waiting for the `lb-phone` resource to start.

**First Troubleshooting Step:** Start `lb-phone` if phone integration is expected.

#### WRN-202 {#wrn-202}

**Internal Key:** `WRN_LUXART_RESOURCE_DEFAULTED`

**Meaning:** **Luxart resource name** was blank, so the resource used `lvc`.

**First Troubleshooting Step:** If your Luxart resource has a different name, enter it in **FiveM Settings > Calls and integrations > Game resources > Luxart resource name**, then restart.

#### WRN-203 {#wrn-203}

**Internal Key:** `WRN_API_REQUEST_FAILED`

**Meaning:** A Sonoran Radio API request failed.

**First Troubleshooting Step:** Inspect the logged request type and reason, then verify API connectivity.

#### WRN-204 {#wrn-204}

**Internal Key:** `WRN_API_ENDPOINT_UNREGISTERED`

**Meaning:** An API request was attempted for an endpoint type that is not registered.

**First Troubleshooting Step:** Register the endpoint type before making that request.

#### WRN-205 {#wrn-205}

**Internal Key:** `WRN_GEO_ZONE_SYNC_FAILED`

**Meaning:** Geo and degrade zones could not be synchronized with the radio service.

**First Troubleshooting Step:** Check the earlier API response details for the zone sync request.

#### WRN-206 {#wrn-206}

**Internal Key:** `WRN_COMMUNITY_CHANNELS_FETCH_FAILED`

**Meaning:** Community channels could not be fetched for a player request.

**First Troubleshooting Step:** Check the HTTP status in the warning and verify the player has valid access to radio data.

#### WRN-207 {#wrn-207}

**Internal Key:** `WRN_SKIN_SAVE_DEBUG_BLOCKED`

**Meaning:** A client attempted to save a radio skin while debug mode was disabled.

**First Troubleshooting Step:** Verify the caller is expected and only enable this workflow while debugging.

#### WRN-208 {#wrn-208}

**Internal Key:** `WRN_CONFIG_RENAME_FAILED`

**Meaning:** A default configuration file could not be renamed to its writable target path.

**First Troubleshooting Step:** Check whether the destination file already exists or is locked.

#### WRN-209 {#wrn-209}

**Internal Key:** `WRN_CONFIG_SAVE_FALLBACK`

**Meaning:** Saving a configuration file failed, so Sonoran Radio fell back to writing the default file.

**First Troubleshooting Step:** Check write permissions on the preferred config file path.

#### WRN-210 {#wrn-210}

**Internal Key:** `WRN_SERVER_IP_USING_EXISTING_ROOM`

**Meaning:** The server IP update failed, but an existing `roomId` was reused while retrying in the background.

**First Troubleshooting Step:** Confirm the existing `roomId` is still valid and investigate the API failure.

#### WRN-211 {#wrn-211}

**Internal Key:** `WRN_SERVER_IP_RETRYING`

**Meaning:** The server IP update failed and will be retried.

**First Troubleshooting Step:** Check API availability and confirm the configured credentials are correct.

#### WRN-212 {#wrn-212}

**Internal Key:** `WRN_SERVER_ID_CONFIG_WRITE_FAILED`

**Meaning:** The resource could not write the assigned Radio server ID to `config.lua`.

**First Troubleshooting Step:** Check whether `config.lua` is read-only or locked. [Fix resource file permissions](/radio/tutorials/usage/troubleshooting/read-and-write-permissions)

#### WRN-213 {#wrn-213}

**Internal Key:** `WRN_APIKEY_CONVAR_UNINITIALIZED`

**Meaning:** The `apiKey` convar was not initialized from `sonoranradio.cfg`.

**First Troubleshooting Step:** Ensure `sonoranradio.cfg` is executed before the resource starts.

#### WRN-214 {#wrn-214}

**Internal Key:** `WRN_CHATTER_EXCLUSIONS_OVERWRITE_DEPRECATED`

**Meaning:** An older resource overwrote the saved earpieces with an older set of rules.

**First Troubleshooting Step:** Keep a copy of your original files. [Update and migrate](/radio/game-integrations/fivem/installing-the-in-game-resource#migrate-existing-settings), then review **FiveM Placements > Earpieces**.

#### WRN-215 {#wrn-215}

**Internal Key:** `WRN_CHATTER_EXCLUSIONS_DEPRECATED`

**Meaning:** The resource detected earpieces defined in the older configuration format.

**First Troubleshooting Step:** After [migrating](/radio/game-integrations/fivem/installing-the-in-game-resource#migrate-existing-settings), use **FiveM Placements > Earpieces** or the in-game menu.

#### WRN-216 {#wrn-216}

**Internal Key:** `WRN_MOBILE_REPEATERS_CONFIG_MIGRATED`

**Meaning:** An older resource imported the vehicle repeater list into its local placement file.

**First Troubleshooting Step:** After [migrating](/radio/game-integrations/fivem/installing-the-in-game-resource#migrate-existing-settings), use **FiveM Placements > Mobile repeaters** or `/radiomenu` to edit vehicles.

#### WRN-217 {#wrn-217}

**Internal Key:** `WRN_LISTENER_PRO_REQUIRED`

**Meaning:** Nearby radio chatter and scanners were disabled because the community does not have a Pro subscription.

**First Troubleshooting Step:** Check the community subscription or disable **Radio chatter and scanners** in **FiveM Settings > Radio > Radio and audio**. Restart the resource after changing the setting.

## Support Diagnostic Uploads {#support-diagnostic-uploads}

When staff select **Request Radio Debug** on your ticket, run `sonoranradio support <ticket ID>` in the **server console** using the supplied ticket number. This requires a resource version that includes the support command. The ticket must have debug uploads enabled by staff.

The diagnostic attachment includes the effective core configuration, separately stored configuration files with credential fields redacted, dependency states and versions, resource uptime, player count, retained error/warning counts, and recent console/debug output. The ticket also displays a compact runtime snapshot before the deduplicated error/warning summary.

Files are labeled as loaded, default-only, missing, invalid JSON, unreadable, or omitted because of size. Disk snapshots may differ from settings already loaded into memory; diagnostics do not execute or rewrite any configuration. Large logs keep the newest console output and explicitly report omitted bytes, entries, or files so the upload can stay below 1 MB. Counts cover the retained buffer rather than all events since startup. Debug mode is left unchanged.

Radio snapshots include `earpieces.json`, `jammers.json`, `scanners.json`, `speakers.json`, `towers.json`, and `mobileRepeaters.json`, with their default-file fallbacks labeled. The runtime section also includes initialized/API-error state, subscription level, active geo/degrade zones, and tower/rack/cell-repeater counts.

Console logs can contain third-party output; only upload to your own support ticket.

#### ERR-124 {#err-124}

**Internal Key:** `ERR_SUPPORT_INVALID_ID`

**Meaning:** The support ticket ID is invalid.

**First Troubleshooting Step:** Run the support command with the positive ticket number provided by staff.

#### ERR-125 {#err-125}

**Internal Key:** `ERR_SUPPORT_COLLECT_FAILED`

**Meaning:** Support diagnostics could not be collected.

**First Troubleshooting Step:** Check the resource configuration and restart it, then retry the command.

#### ERR-126 {#err-126}

**Internal Key:** `ERR_SUPPORT_TOO_LARGE`

**Meaning:** Support diagnostics still exceed the 1 MB upload limit after automatic size handling. Large console logs are normally clipped automatically.

**First Troubleshooting Step:** Ask support for another way to send the log.

#### ERR-127 {#err-127}

**Internal Key:** `ERR_SUPPORT_UPLOAD_FAILED`

**Meaning:** Support diagnostics could not be uploaded.

**First Troubleshooting Step:** Verify the ticket ID, ask staff to enable debug uploads, and check outbound HTTPS connectivity to api.sonoransoftware.com. A timeout or non-success response does not confirm delivery.

## Legacy Troubleshooting Codes {#legacy-troubleshooting-codes}

The entries below are older support references that may still appear in existing guides, logs, or support replies.

### ERR 101: Unable to get a valid pushUrl {#err-101-unable-to-get-a-valid-pushurl}

Sonoran Radio uses your CFX Nucleus Proxy URL to send push events from the radio to your game server. For example, this allows playing a tone on the radio to an in-game speaker.

In the event that Sonoran Radio cannot obtain or verify your CFX Proxy URL, it tries to use your server's public IP address as a backup for push events. On some hosts, that fallback may also fail.

If the host provides a reachable push endpoint for the managed resource, set `sonoranradio_pushUrl` in `server.cfg` before the Sonoran Radio startup command. Use the full HTTP(S) URL, including the `/sonoranradio/events` path.

If this does not resolve the issue, contact your host provider. They are likely blocking inbound traffic to your server.

### ERR 102: No push event URL set {#err-102-no-push-event-url-set}

Sonoran Radio uses your CFX Nucleus Proxy URL to send push events from the radio to your game server.

1. Check your server console for `ERR 101`. That error indicates a problem setting or validating the push URL.
2. If you are using a non-FiveM server but still utilizing push events, ensure the `pushUrl` property is sent with a full HTTP(S) address with the [set-server-ip API endpoint](/radio/developer-documentation/developer-documentation/api-endpoints-v2/community-server/set-server-ip).
